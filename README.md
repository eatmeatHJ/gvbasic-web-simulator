# GVBASIC 模擬器

在瀏覽器裡執行文曲星 / 哈電族的 GVBASIC 程式（`.BAS`）。模擬器本身不含任何遊戲：選一個資料夾，在選單裡挑程式執行。

## 使用

1. 雙擊 [web/index.html](web/index.html)（或執行 [serve.bat](serve.bat)，用 `http://localhost:8765/` 開啟）。
2. 按「**選擇資料夾…**」，挑一個放有 `.BAS` 的資料夾（要先試試的話，[demo/](demo/) 有幾個小示範）。本倉庫不附任何遊戲或程式，請用你自己的。
3. LCD 上會出現像真機的檔案選單：`↑` `↓` 選擇、`Enter` 開啟／執行、`←` 或 `Esc` 回上層。右邊面板是同一份清單，也可以用滑鼠點。
4. 程式結束後按任意鍵回到選單；按「■ 停止」也會回到選單。

### 資料夾與檔案

- **BAS** 是程式，**DAT** 是資料檔（官方文件的稱呼）。程式 `OPEN "名稱"` 時，檔名會自動補上 `.DAT`（已有 `.DAT` 結尾則不補），大小寫不分。
- DAT 一律以「**程式所在的資料夾**」為準：從 `a/b/` 執行的程式，讀寫的是 `a/b/` 裡的 `.DAT`，不會碰到別的資料夾。
- 子資料夾可以逐層進入；選單只列出資料夾、`.BAS`、`.DAT`。
- **Chrome / Edge**：存檔直接寫回實體資料夾（第一次需要授權，下次會記得上次開的資料夾）。
- **其他瀏覽器**：只能讀取；程式寫出的 DAT 暫存在瀏覽器，可用「下載」取出。

### 編輯程式（像真機的修改鍵）

選單裡：`F1` 新增、`F2` 刪除、`F4` 修改（螢幕上的按鍵、電腦鍵盤、右側面板的「修改」按鈕都可以）；程式執行中 `F1`–`F4` 是按鍵碼 28–31。

- **編輯畫面**就是真機的行編輯器：每行以行號開頭，長行會折到下一列。方向鍵移動、`Enter` 換行（接在最後一行時自動補下一個行號，+10）、`Backspace`／`Delete` 刪字、`Insert` 切換插入／覆蓋。行號後面什麼都不寫再存檔 = 刪掉那一行；行號重複時以後面那行為準；存檔時會依行號排序。
- **按 `Esc` 結束編輯並儲存**：畫面變成 `Input file name:`，輸入檔名（不用打 `.BAS`）後按 `Enter` 存檔；同名檔案會先問是否覆蓋。真機在這個畫面按 `Esc` 是取消並丟掉修改，這裡改成「回到編輯」以免誤丟。**要放棄修改直接離開，按 `F2`**（螢幕上的 `F2 刪除` 在編輯時會變成 `F2 放棄`，檔名畫面也會顯示 `F2:Discard edits`；右側面板也有「放棄修改」按鈕）。沒改過就直接離開，有改過會先確認（`Enter` 放棄、`Esc` 繼續編輯）。
- **沒改的行原封不動**：存檔時沒動過的行直接寫回原本的位元組，只有你改過的行才會重新轉成 token（關鍵字會轉大寫，格式與真機一致）。
- 儲存是寫回你選的資料夾（Chrome / Edge），或存在瀏覽器裡（其他瀏覽器）。
- 鍵盤預設「直接輸入」（不受系統輸入法影響，注音開著也能打英數）；要打中文，按狀態列的「輸入：直接」或螢幕上的「輸入法」鍵切到中文輸入法。`INPUT` 進行中，狀態列顯示電腦現在是大寫還是小寫。螢幕上的「數字鍵」切換後，字母鍵會打出鍵上標的數字，另有一列符號鍵。
- **誤按 F5 不會中斷程式**：程式執行中、或編輯畫面開著的時候，F5（和 Shift+F5）會被攔下，狀態列顯示「F5 已攔下」；要重新整理請按 Ctrl+R 或瀏覽器的重新整理鈕。程式執行中、或編輯有尚未儲存的修改時，重新整理／關閉分頁前瀏覽器會先問一次。在檔案選單裡 F5 照常重新整理。
- 關鍵字的 token 編號全部取自官方轉換程式內建的表（110 個關鍵字，見 [docs/官方轉換程式.md](docs/官方轉換程式.md)），所以從這裡存出去的 `.BAS` 與官方轉換程式的結果用同一套編號。

### 機器碼：`CALL` 與 `.BIN`

BASIC 之外，這個模擬器也能執行 6502 機器碼（文曲星的 CPU 就是 6502），做法像 DOS 模擬器：CPU 用模擬的，**系統常式用 JS 重寫**。

- **`CALL 位址`**：在模擬的 6502 上執行那段機器碼，遇到最後的 `RTS` 回到 BASIC。機器碼和 BASIC 共用同一份 64 KB RAM：`POKE`/`PEEK` 寫進去的東西機器碼看得到，文字畫面（RAM `$02C0`）和圖形畫面（RAM `$19C0`–`$1FFF`，1 位元壓縮）也是兩邊共通的。
- **系統調用**：機器碼用 `INT $xxxx`（三位元組指令，機器碼 `00`）或 `JSR $E0xx` 呼叫機器的系統常式；模擬器攔下來，由 [web/wqxos.js](web/wqxos.js) 處理。目前有：清屏、更新 LCD、讀按鍵、延時、電量、畫線／方塊／圓／橢圓（含填滿）、訊息框、讀快閃（空實作）。規格與出處見 [docs/文曲星-系統調用.md](docs/文曲星-系統調用.md)。
- **沒實作的呼叫會被明確指出**：例如「Unimplemented system call INT $C999」「Unimplemented BIOS routine $E135」，下一個該做什麼一目了然。
- **小型 `.BIN`**（小於 8 KB、檔頭 `AA A5 5A`，格式見上述文件）可以直接從選單執行。
- **大型機器碼映像（`.bin`，整數頁 × 32 KB）**：在選單選它按 Enter 或按列上的「▶ 安裝」，就像在真機上把它裝進快閃。（「安裝」就是有些說明書說的「植入」；真機第一次執行大型 BIN 時顯示的是「裝入中…」。）安裝後，同一個資料夾（含子資料夾）裡呼叫機器碼的程式會在「大陸機種」模式跑：`$4000`–`$BFFF` 是分頁視窗（分頁暫存器是零頁 `$00`，第 k 頁 = `PEEK(0)+k`）、螢幕 RAM 在 `$09C0`、字集是 GBK（程式裡的 Big5 字串自動轉碼）、BASIC 的 `CALL` 直接進入映像裡的機器碼。映像只存在你的瀏覽器（IndexedDB）。細節見 [web/flash.js](web/flash.js)。一個 RPG 的引擎映像（`GVbasic+.bin`）就是這樣跑起來的（檔案必須自備，不在專案裡）。
  - **可以裝多個**：每個映像只對「裝它的那個資料夾」（含子資料夾）生效，不同資料夾可以各有自己的映像；同一個資料夾再裝一個，會取代原來那個（選單會寫「取代了…」）。一個程式用哪個映像：看它所在的路徑，離它最近的那個資料夾裡裝的映像。資料夾是用名稱比對的（不是完整路徑）。
  - **管理**：側欄的「已安裝的機器碼映像」卡片列出全部（名稱、頁數、適用的資料夾），每個都有「移除」，兩個以上時還有「全部移除」；檔案列表裡已安裝的那個 `.bin` 會標「已安裝」（按鈕變成「重新安裝」和「移除」），進入適用的資料夾時列表上方有一行提示；程式執行中，狀態列寫著「映像：名稱」。
  - **怎麼分「安裝」和「直接執行」**：檔頭分不出來——每個放進快閃的程式都有同樣的標準 BIN 檔頭（`$4018` 是 `4C` JMP、`$401B`–`$401D` 是 `A5 AA 55`），上述引擎映像也有。所以模擬器列資料夾時**試跑**一下（在只有晶片、沒有 ROM 的硬體層上跑最多 20 萬個指令）：自己讀鍵盤的機器碼遊戲整段都不碰系統 ROM，就按 Enter 直接執行；一啟動就呼叫系統 ROM（`INT` 或跳進 `$C000` 以上）的，例如上述引擎映像，要靠真機的 BIOS，不能自己跑，按 Enter 只會安裝。選單的狀態列和側欄寫明是哪一種，並有第二顆按鈕可以反過來選（「當遊戲試跑」／「改成安裝」）；強制當遊戲跑一個需要 BIOS 的映像，會停下並提示「改用安裝」。
  - **安裝之後**：LCD 會顯示「已安裝 …／適用：資料夾名稱／進入資料夾執行 BAS」，按任意鍵回選單，游標已經停在第一個資料夾上（引擎映像的遊戲放在子資料夾裡）。按 Enter 進去，選遊戲的主程式（`.BAS`）再按 Enter 才是進遊戲。
- **CPU**：[web/cpu6502.js](web/cpu6502.js) 是原版 NMOS 6502，通過 Klaus Dormann 的標準功能測試（`node web/test_cpu.js`）。[web/asm6502.js](web/asm6502.js) 是測試與示範用的小組譯器。
- **示範**：[demo/](demo/) 有三個我寫的小程式（`HELLO.BIN` 顯示文字、`DRAW.BIN` 畫圖、`CALLDEMO.BAS` 用 `POKE` 寫入機器碼再 `CALL`），選這個資料夾就能試。重新產生：`node tools/make_demo.js`。
- **已知缺口**：書上 `INT $8A15` 的「小字」模式（`(0402)=1`）還沒做；延時的單位、訊息框與橢圓的尺寸是依書的描述估計的。大型映像用的 BIOS 常式（`$E135` 等）是從呼叫方式推斷的，見 [docs/大型機器碼映像.md](docs/大型機器碼映像.md)，還有數個沒做。

### 選單上的檔名

LCD 選單像台灣機種一樣用 Big5。資料夾裡只要有一個檔名含簡體字（Big5 沒有的字，例如 `棋盘.txt`），整個選單就改用 GBK 顯示（GBK 同時有簡體和繁體），所以簡體檔名可以正常看到；側欄的清單一直都是完整的 Unicode。兩種字集都沒有的字（例如表情符號）還是顯示成 `?`。

### 文字檔（.txt）轉 .BAS

別人分享的 GVBASIC 程式常是「行號加敘述」的文字檔。資料夾裡看起來像程式的 `.txt`（八成以上的行以行號開頭）會出現在選單裡：

- **轉成 BAS**（主要動作）：列上的「⇄」、點檔名、或選到它按 Enter，把它存成同名的 `.BAS`（已存在會先問）；轉好之後那一行就有 ▶ 可以執行、✎ 可以修改。能不能轉成真機的 BAS 看下面「別的模擬器的專屬語法」。
- **試跑（不存檔）**：列右邊的「⋯」→「試跑（不存檔）」，或選到它按 Shift+Enter，即時轉成 BAS 在記憶體裡跑，不寫任何檔案。用了模擬器專屬語法、不能存成真機 BAS 的文字檔，只能這樣跑。
- **BAS 轉文字**：BAS 那一行的「⋯」→「存成 TXT」，寫成同資料夾的 `名稱.txt`（已存在會先問；唯讀來源的資料夾改成下載）。內容是「原始碼」顯示的那份清單，UTF-8 加 BOM、CRLF 換行，再用「轉成 BAS」轉回來得到同一支程式（範例程式 26 支全部通過測試）。
- **命令列**：`node tools/txt2bas.js <檔案或資料夾> -o 輸出資料夾`，可選 `--charset auto|big5|gbk`、`--base 7000`、`--force`（略過失敗的行）。程式碼在 [web/txt2bas.js](web/txt2bas.js)，網頁與命令列用同一份。
- 文字可以是 UTF-8 或 GBK（附 BOM、CRLF、結尾的 Ctrl-Z 都可以）；`{FA48}` 這種「大括號加四位十六進位碼」會原樣寫成那個機器內碼（本專案的原始碼清單就是這樣顯示圖形字的）。
- **字集**：中文寫成 Big5（台灣機種，本專案預設）或 GBK（大陸機種）。`auto` 的規則：所有字都能用 Big5 表示就用 Big5，否則（簡體字）用 GBK。執行 BAS 時字集從文字自動判斷（至少 6 個中文字、第二位元組全部 ≥ A1 且第一位元組多在 B0–F7 → GBK），判斷錯了可在側欄「BAS 字集」指定。程式編輯器（`F4` 修改）也照檔案的字集顯示與重新編碼：簡體文字轉出來的 BAS 是 GBK，編輯時就用 GBK（`BAS 字集` 設定可以強制），新程式用 Big5；沒改動的行原樣寫回，改過的行用同一個字集重新編碼。
- **別的模擬器的專屬語法**：`SLEEP`、`PAINT`、`LOAD addr,size,…`、`FPUTC`、`FWRITE`、`FREAD`、`FSEEK`、`POINT()`、`CHECKKEY()`、`FOPEN()`、`FGETC()`、`FTELL()`、`OPEN … FOR BINARY` **不是真機的語言**，是 [arucil/gvbasic-simulator4cpp](https://github.com/arucil/gvbasic-simulator4cpp) 自己加的擴充（見它的 `language.md`），真機的 `.BAS` 不可能含有它們，也沒有記號碼。處理方式：
  - **試跑**（「⋯」→「試跑（不存檔）」／Shift+Enter）：只有這些字擋路時，模擬器改用「擴充模式」在記憶體裡轉換並執行（用內部記號碼 `EE`–`F9`），狀態列會寫「這支程式用到 arucil 模擬器的擴充語法」。這種模式也接受小寫。
  - **轉成 BAS／命令列**：照實拒絕並列出每一行，不會寫出真機沒有的記號碼；提示會告訴你改用試跑。
  - `SLEEP n` 等待 n × 0.4 毫秒（arucil 的 `sleepfactor`；選「全速」時不等）。`CHECKKEY(k)` 看的是按鍵目前有沒有按住（鍵碼與 `PEEK(199)` 讀到的相同）。`PAINT` 的圖樣是 RAM 裡的 1 位元點陣（每列 ⌈w/8⌉ 位元組，最左點是最高位元），模式 0 複製、1 或、2 反相、3 且、4 互斥或。
  - 一般（非擴充）程式裡寫 `POINT(` 這類名字只會得到警告（真機上它是名叫 POINT 的陣列）。`RESUME` 手冊提到但官方轉換程式沒有它的記號碼，同樣拒絕。
- 與官方轉換程式的差異：我們保留你打的空白（真機的輸入會去掉）；`OPEN … LEN=n` 的 `LEN` 照真機留成字母。

用了 `SLEEP`、`FREAD` 這類 arucil 專屬語法的文字檔不能存成真機的 `.BAS`，只能「試跑」。

### 不需要轉換

`.BAS` 直接由 [web/gvb.js](web/gvb.js) 解析 token 位元組並執行，沒有轉換步驟，也不需要 Python。面板上的「原始碼」按鈕即時還原成可讀文字（原檔不會被改動）。

測試（都是 Node，不需要瀏覽器）：

- `node web/test_cpu.js`：6502 CPU 的標準功能測試（需要 `ref/cputest/` 裡的測試檔）與幾項直接檢查。
- `node web/test_machinecode.js`：機器碼、系統調用、與 BASIC 共用記憶體、小型 BIN。
- `node web/test_editor_charset.js`：程式編輯器照檔案的字集（Big5／GBK）顯示、游標、重新編碼，沒碰的行原樣寫回。
- `node web/test_hw.js`：硬體層（遊戲檔頭偵測、計時器旗標當影格同步、鍵盤矩陣、CPU 等待時休眠），用測試裡自己做的小遊戲。
- `node web/test_txt2bas.js`：文字 → `.BAS`（編碼、排序、刪行、錯誤收集、Big5／GBK、`{FA48}`），以及（有樣本程式時）「清單 → 文字 → `.BAS` → 清單」「`.BAS` → `.txt` → `.BAS`」完全一致。
- `node web/test_compat.js`：從真實程式發現的語言細節（`SWAP`、數字中的空白、`INPUT#`／`EOF`、`FILE OPEN`、`DATA`／`READ`），以及 token 編號、`CLEAR`／`POP`、`MKI$`／`MKS$`、隨機檔與檔案錯誤名稱（真韌體量到的）、運算子優先順序、數字的列印格式、`RND`、`PRINT` 對 `CHR$(0)`、小寫名字。
- `node web/test_extensions.js`：arucil 專屬語法（`SLEEP`、`PAINT`、`POINT`、二進位檔……）的轉換與執行，包含「不會被寫進真機的 BAS」。

## 已確認的真機行為（依據 arucil/gvbasic-simulator4cpp，MIT）

- 螢幕 160×80；文字 20 欄 × 5 列；全形字佔 2 欄。
- `PRINT`：逗號換行、分號不換行；數字以 `%.9G` 輸出；游標在第 0 欄時不會多換一行。
- **文字與圖形的關係**：`TEXT` 模式下文字是螢幕上的一層，`CLS`、`LOCATE` 後覆蓋才會改變；`GRAPH` 模式下 `PRINT` 的字是**當場畫進圖形點陣**的（arucil 的 `updateLCD` 也是這樣），所以之後的 `BOX`（清除）、`LINE`、機器碼捲動螢幕 RAM 都會直接作用在字的點上。而且每個 `PRINT`（與 `INPUT` 的提示）結束時，會把**整個文字 RAM 的每個字再畫一次**（arucil 的 `updateLCD`）：空白會擦掉它那一格。有的地圖編輯器靠這個移動選單標記——標記用 `BOX` 畫在選項前面的空白格裡，下一次 `PRINT " "` 就把舊標記擦掉。副作用是：用 `BOX` 清掉的舊文字，只要它還留在文字 RAM 裡，下一個 `PRINT` 會讓它重新出現（arucil 也是這樣，真機是否如此沒有直接驗證，只有這幾個程式的寫法與 arucil 的行為互相吻合）。還有一支隧道捲動遊戲也靠這個：開場作者的名字畫在圖形上，畫面捲動 160 次後字就被捲出畫面；以前文字是獨立一層，捲不動，一直擋在畫面中間。
- **繪圖演算法**：`LINE` 用「點 i 的位置 = floor(i × d ÷ 長度)」的步進（不是 Bresenham，整條線和四捨五入的版本差半格）、`CIRCLE`／`ELLIPSE` 用中點演算法，都和 arucil 的程式碼逐像素相同（我拿 12,221 條線、76 個圓逐一比對過）。繪圖模式只看 `值 & 3`：0 清除、1 畫、2 反相、3 什麼都不畫（有的程式的轉場效果用到模式 3）。`BOX` 的右下角先被裁到螢幕內（超出螢幕的外框會畫在最後一欄）；座標超過 255 當成 255、負的座標是錯誤；填滿參數只要不是 0 就填。`POKE 199,155` 會結束程式（等於按了 Esc，好幾支樣本程式用它離開）。
- `INKEY$` 會阻塞等待按鍵；`FOR` 迴圈至少執行一次；`AND`/`OR`/`NOT` 為邏輯運算。
- `IF…THEN/ELSE` 內「裸行號」等同 `GOTO`。
- 按鍵碼（NC3000 真韌體量到的，完整表見 [docs/按鍵碼.md](docs/按鍵碼.md)）：上 20、下 21、右 22、左 23、Enter 13、Esc 27、刪除 29、求助 25、輸入法鍵 26、大小寫鍵 18、F1–F4 28–31、翻頁鍵 19／14（哪個上哪個下是推測）；字母永遠是小寫碼；數字鍵疊在字母鍵上（`b n m`=1 2 3、`g h j`=4 5 6、`t y u`=7 8 9）。
- 資料檔：`"字串"` 加引號、數字用 `%.9G`、逗號分隔、一筆記錄以 `0xFF` 結尾。

## 尚未確定／已知差異

- **時鐘**：`PEEK(1015)` 是小時（原本只是從程式的用法推斷，現在得到 NC3000 韌體確認），同一排的 `PEEK(1016)`–`PEEK(1021)` 依序是分、秒（偶數）、年 − 1881、月 − 1、日 − 1、星期（0 = 星期日），模擬器照這個排列回答（小時可在側欄指定時段，其他取電腦的時間）。排列的依據與韌體的預設日期見 [docs/NC3000韌體.md](docs/NC3000韌體.md)。
- **字型**：英數字、GB2312 中文字（簡體機型、`GBK` 字集）、機器自己的圖形字（GB 碼 `F8A1`–`FDD9`，527 個）和大型映像用的 12×12 小字，**都是真機的點陣字型**（資料取自 arucil 專案的 `res/`，MIT；檔案在 `ref/arucil/res/`，授權見 `ref/arucil/LICENSE`。這些資料原本出自機器的 ROM，所以請當成參考資料看待）。台灣機型（Big5）的中文字型我們沒有：用系統內建的點陣明體（MingLiU），沒有的系統會退到其他字型，字形可能略有差異。字型資料要重新產生時執行 `python tools/build_web.py`。另一份真機韌體（NC3000）裡的字型表（位置、格式、和 arucil 的比較：英數字與 527 個圖形字相同，漢字與符號是另一套畫法、依 Unicode 排序、含繁體）整理在 [docs/NC3000韌體.md](docs/NC3000韌體.md)，只記事實，不含資料。
- **圖形字**：機器內建的 527 張小圖（花色、方向箭頭、房子、圖示）有真機的點陣（GB 碼 `F8A1`–`FDD9`），台灣機型（Big5 `FA40` 以後）和簡體機型的 RPG 引擎（`FA40` 以後的道具圖示）用的是**同一批圖**，只是編號不同。程式裡找到兩種編號（A：從 `FA40` 起、只有真正的 Big5 碼；B：從 `FA46` 起、一路數下去），證據與判斷方式見 [docs/圖形字編號.md](docs/圖形字編號.md)；網頁設定的「圖形字編號」預設自動判斷，也可以手動選 A、B，或只顯示代碼方框。圖對不上任何一種的碼（超出 527 張、或是空白圖）仍顯示成「帶框的小方塊加四位十六進位碼」。哪一種編號屬於哪個機型沒有真機可以核對，自動判斷是從程式用到的碼推的。簡體機型這一側還有一個衝突：GBK 自己也把 256 個常用繁體字放在 `FA40`–`FEA0`（`麼 點 龍 黃 麥 鹽 黨 鶴 齊 麗` …），Big5 程式的文字轉成 GBK 之後就會被誤畫成方框。所以在簡體機型上，轉換（以及中文輸入法打的字）會把這些字改存到 GBK 的使用者自訂區 `A140`–`A7A0`（機器沒有用到），顯示時再查回原字；寫給真機的檔案（`txt2bas --charset gbk`）仍用真正的 GBK 碼。
- **token 編號已由官方轉換程式的表確認**（過去標為推測的 `GRAPH`、`CLS`、`BEEP`、`SWAP`、`FIELD`／`GET`／`PUT`／`LSET` 等全部相符；只有 `TEXT` 原先猜錯：`9B` 是 `CLEAR`，`TEXT` 是 `9D`）。
- 程式結束後的「按任意鍵返回選單」停留是為了讓你看到最後的畫面，真機是否相同尚未確認。
- **不支援的關鍵字**：`SYSTEM`、`LOAD "檔名"`、`SAVE`、`KILL`、`FILES`、`RENAME`、`COPY`、`AUTO`、`EDIT`、`LIST`、`NEW` 在官方轉換程式的 token 表裡有編號，但裝置的 BASIC 說明沒有把它們列為可用語句（語句清單裡沒有），arucil 的模擬器也沒有實作，我們檢查過的 43 支樣本程式沒有一支用到。所以這不是「還沒做」，而是真機的行為沒有任何資料可依：執行到會報 `UNSUPPORTED STATEMENT: 名稱`。`TRACE`、`NOTRACE`、`CONT` 當成不影響執行的空語句（arucil 對 `CONT` 也是忽略）。`INVERSE`（反白）、`NORMAL`、`FLASH`（閃爍，半秒一次）會標在之後印出的每個字元格上，`CLS` 清掉標記；文字改寫時（例如 `LOCATE` 後覆蓋）標記跟著新印的字走；`POKE` 寫文字 RAM 不會改動標記。`CLEAR` 的細節（是否重設 DATA 指標、是否關閉檔案）手冊沒寫，照 arucil 的實作。`MKS$`／`CVS$` 的 5 位元組格式（指數在前、尾數 4 位元組高位在前、符號在第 2 個位元組的最高位，`MKS$(1.5)` = 129,64,0,0,0）是在 NC3000 真韌體上讀回來的，先前照 arucil 寫的（指數在最後、低位元組在前）和真機不同，已經換掉。
- **隨機檔**（`OPEN … FOR RANDOM [LEN=n]`、`FIELD`、`LSET`／`RSET`、`GET`／`PUT`、`LOF`）：語法來自手冊，細節已在真韌體上量過（[docs/NC3000韌體.md](docs/NC3000韌體.md)「語意驗證」）：一筆記錄是一塊緩衝區，欄位變數是它的視窗（兩個 `FIELD` 敘述會共用位元組，對欄位變數直接賦值會讓它脫離緩衝區）；沒有 `LEN` 時一筆 32 位元組；`LSET` 蓋在變數開頭、剩下的維持原樣，`RSET` 整個寬度重寫、左邊補空格；`PUT` 不能留空洞；`LOF` 是檔案位元組數、`EOF` 為真時是 1；錯誤名稱照韌體（沒開的檔案在敘述裡是 `SYNTAX`、在 `LOF`／`EOF` 是 `FILE MODE`）。
- **字串變數的記憶體表**：真機的直譯器把字串變數放在 RAM 的一張表裡（每個 5 位元組：名字字母、長度、位址低、位址高、另一個位元組，從 12605 起，依第一次賦值的順序）。有的程式自己去表裡找 `A$` 和 `B$`（掃描 `PEEK(A)=65 AND PEEK(A+5)=66`），再 `POKE` 長度與位址，讓 `A$` 變成一扇看著任意記憶體的窗；之後 `LSET` 就是在那塊記憶體和檔案記錄之間複製位元組（存檔、讀檔就是這樣做的）。直譯器現在模擬這張表：值本身仍是 JavaScript 字串，只有表項被 `POKE` 過的變數才讀寫記憶體；一般賦值會讓它回到自己的儲存空間，`CLEAR` 重新開表。
- **快閃存檔**：程式可以把存檔寫進映像裡空著的快閃頁（引擎自己的 RAM 常式照 AMD 快閃的指令序列做：AA/55 解鎖，`80 AA 55 30` 清除 4 KB 磁區，`A0` 加一個位元組是寫入，`F0` 復位）。映像的位元組會被改掉，改過的複本留在這個瀏覽器（隔一下就存），重新整理後還在；「重新安裝」把它還原成原檔，存檔就沒了。操作立即完成，所以程式輪詢狀態位元時一次就看到結果。
- **運算子優先順序**（在 NC3000 真韌體上量過，見 [docs/NC3000韌體.md](docs/NC3000韌體.md)）：`^` 由左到右（`2^3^2` = 64）；`AND` 比 `OR` 優先（`1 OR 0 AND 0` = 1、`0 AND 1 OR 1` = 1）；`AND`／`OR`／`NOT` 的結果只有 0 和 1；`NOT` 是前置運算子，比 `*`、`+` 和比較運算結合得更緊（`NOT 1+1` = 1，`NOT A=1` 是 `(NOT A)=1`，`NOT 0*5` = 5）。先前依 arucil 寫成「`AND`／`OR` 同一級由左到右」「`NOT` 比比較運算低」，真機不是這樣，已經改掉。
- **`RND`**：用 NC3000 真韌體的產生器（5 位元組浮點數，Applesoft 一類：種子乘 11879546、加 3.92767778E-8、對調尾數最高與最低位元組、舊指數當延伸位元組、正規化後四捨五入；`RND(0)` 重複上一個值，`RND(<0)` 依 `|x|` 重設成固定的數列，`RND(x>0)` 不看 x）。在真韌體上連續 59 步逐位元組比對一致，`RND(-1)` 後的 .738207502、.272707136、.299733446 與 `RND(-3)` 後的 .235586735、.186784665 也一致（細節見 [docs/NC3000韌體.md](docs/NC3000韌體.md)）。先前用的 16 位元產生器（來自 arucil）和真機不同，已經換掉。沒有設種子時的起始值在真機上每次開機不同，這裡是隨機的。
- **小寫變數名**：真機報 SYNTAX ERROR（fancyblock 在真機上試出來的）。本模擬器對 `.BAS` 裡的小寫名字照樣報 SYNTAX ERROR（40 支現有程式、7405 行沒有一處中招）；文字轉 `.BAS` 時一律寫成大寫並附警告。
- **沒跟著 arucil 的地方**（有真機程式證據反對）：`MID$(s$,n)` 省略長度時，arucil 取 1 個字元，一套多檔案 RPG 的程式（`MS$=MID$(MS$,2)`、`X$=MID$(I$,2)`）明顯要「到字串尾」，我們維持後者。arucil 的 `DIM a`（不帶括號）、`INPUT 1,…`／`WRITE 1,…`（沒有 `#`）也沒採用：手冊的語法有 `#`，沒有 `#` 的 `WRITE` 是寫到螢幕。
- **和 arucil 不同、但維持現狀的兩處**：`INPUT` 輸入的長度上限（我們 255，arucil 254），以及對鍵盤矩陣位元組的 `POKE`（arucil 會忽略，我們照寫進 RAM）。兩處都只有 arucil 一個來源，沒有真機資料或樣本程式支持任何一邊，所以不改。
- **執行速度**（預設 3,000 語句/秒，可在側欄改）：書、BASIC 說明、參考模擬器、WQXEmu 文件都沒有 BASIC 語句速率。在 NC3000 真韌體的 GVBASIC 上量過（時脈取 10.24 MHz）：只有 `NEXT` 的迴圈每秒約 4,400 圈，加上一個簡單賦值約 1,500–2,200 圈，有乘加的運算式約 1,150 圈，也就是每秒約 1,500–4,400 個簡單語句，預設值落在這個範圍內，沒有改。其他機種沒有數據。用迴圈計時的程式（反應時間、`READY?` 倒數）對它很敏感，沒有延遲迴圈的程式則完全不受影響。
- **機器碼速度**（側欄「機器碼速度」，預設 0.5 MHz）：`CALL` 到的機器碼（大型映像的引擎、小型 `.BIN`）原本全速跑，比真機快幾十倍，所以在引擎的地圖上輕點一下方向鍵，人物就一路走到碰到東西為止（引擎是「按著就走一步、一步接一步」，一步約 2.6 萬條指令，全速時不到 1 毫秒）。現在照設定的 MHz 限速（平均一條指令約 3.3 個週期）。**這個數字不是任何機種的真實時脈**：文件裡只有 NC3000 的 10.24 MHz，而 ROM 常式（畫圖、貼點陣）在本模擬器裡是瞬間完成的，真機實際比時脈算出來的慢；0.5 是實測「手指輕點約 0.1 秒＝走一格」的值。可選全速、5.12、2、1、0.5、0.25 MHz。硬體層機器碼遊戲用幀率控制，不受影響。
- **鍵盤的「按住」**：程式自己讀鍵盤掃描值的（引擎映像、雙人對戰類程式），按鍵放開前一直算「按下」，放開後至少維持 70 毫秒並且被程式讀過一次才放掉（以前是固定 160 毫秒，輕點一下等於按了 0.16 秒）。
- **`PLAY` 的音符格式**（`O4` 八度、`L33` 長度、`CDEFGAB`、空白是休止）是從真實程式字串歸納的；全音符時長（1.6 秒）與八度對照是估計。`BEEP` 是 4485 Hz、50 毫秒的方波，數字是在 NC3000 真韌體上量到的（見 [docs/NC3000韌體.md](docs/NC3000韌體.md)；NC3000 的 CPU 時脈取 10.24 MHz）。同一份韌體的 GVBASIC 把 `PLAY` 當成 `REM`（整行跳過、不發聲），所以 `PLAY` 的音符表沒有地方可查；這裡仍然照 NC1020 一類機型的做法讓 `PLAY` 發聲，是有意保留的差異（使用者自己那台哈電族 NC3000 是另一個版本的韌體，不知道它怎麼處理 `PLAY`）。
- **原始按鍵值（鍵盤矩陣）**：程式用 `PEEK` 讀鍵盤掃描 RAM（8 個位元組，按下的鍵把自己的那一位清成 0，沒按是 `$FF`）。每個鍵的位置取自 arucil 的 `config.ini`（例如 `←` = 第 0 個位元組的 `$80`，`→` = 第 0 個位元組的 `$08`，`P` = 第 3 個位元組的 `$08`，`Q` = 第 7 個位元組的 `$10`）。矩陣從哪個位址開始因機種而異：NC2010／TC808 系列從 `$BF`（191），NC1020 從 `$BC`（188，一支雙人對戰程式的預設值；它的論壇原文：「NC1020 使用者不需做任何更改，NC2010 使用者請更改 P111、P121、P211、P221」，也就是該程式第 4 行的註解和第 6 行的數值）；側欄「鍵盤矩陣（機型）」可以手動選：**自動**（看程式裡有沒有用常數 `PEEK(191)`…`PEEK(198)`：有 → `$BF`，否則 `$BC`，這是啟發式）、**NC1020**（`$BC`）、**NC2010／TC808**（`$BF`），選了就蓋過自動判斷，執行中改也立刻生效。用 NC2010 玩那支程式要照它第 4 行的說明改第 6 行的位址。以前只對了那支程式的猜測鍵位（Q／A、↑／↓），結果另一支用 `PEEK(191)` 的磚塊遊戲只按「上」平台就往右走；現在該程式是 1P `Q`（上砍）與 `Z`（下砍）、2P `P`（上砍）與 `→`（下砍）；這份鍵位是論壇的說明，且和程式第 6 行比對的數值（195/239、195/127、191/247、188/247）一致。其中 `Z` 在 arucil 的表裡是第 7 個位元組的 `$40`，而程式要的是 `$80`，所以 NC1020 的矩陣（起點 `$BC`）把 `Z` 與幫助鍵（25 號）對調了——這是為了符合論壇說明做的假設。不在表裡的鍵（例如有程式用來切換聲音的 26 號鍵）鍵盤上按不到。
- **硬體層機器碼遊戲**（未壓縮的原始分頁，例如入口在 `$402C` 的橫向捲軸遊戲）可以直接執行：它不走 BIOS，直接操作鍵盤埠與計時器，所以另做了硬體層 [web/wqxhw.js](web/wqxhw.js)。在選單選它按 Enter 就會跑（←→ 移動、Z 或空白跳躍、X 加速、Enter 開始，這組鍵依該遊戲的用法安排）。幀率與上、下、暫停鍵是推測，細節與依據見 [docs/硬體層機器碼程式.md](docs/硬體層機器碼程式.md)。
- **無法執行的 BIN**：少數壓縮容器的 BIN（NC2000／NC3000／NC2010 系列的組語遊戲，容器格式不明）目前跑不了（沒有找到解開的辦法）。
- **RPG 引擎映像**可以進遊戲、畫頭像、在地圖上走動、和人對話、叫出 F4 選單。**頭像小工具**（`INT $010A`）現在是我自己做的畫板（真機的樣子與按鍵不明）：方向鍵移動、空白鍵畫點／擦點、`D` 筆（移動就畫）、`E` 橡皮、`C` 清除、`I` 反相、Enter 完成，操作說明顯示在狀態列。**對話文字**靠 ROM 的 6 個字型常式（`$D1BA`、`$CE7E`、`$CED6`、`$D716`、`$CA5F`、`$CEEE`），它們是從引擎 `$BB00` 那段程式的用法推斷、用瀏覽器的字型畫的，不是真機 ROM 的行為；壓力測試（約 210 分鐘的隨機遊玩，包含直接開戰 70 次與事件腳本 37 種指令）只碰到一個沒做的 ROM 常式（道具清單用的 `$E10B`，已實作），其餘沒有錯誤，但沒有人完整玩過。還沒做／未驗證：畫面與數值是否和真機一致、音效。映像裡另有一個 ROM 常式 `$E138`，它只在映像自帶的 BASIC 直譯器的結束路徑上被呼叫，本模擬器用自己的直譯器取代了那一段，永遠不會走到，所以不需要實作。進度與待辦見 [docs/大型機器碼映像.md](docs/大型機器碼映像.md)。
- 官方轉換程式（「GVBASIC 轉換程序 v2.0」，`BasToTxt.exe`）的取得方式與如何從裡面讀出 token 表，見 [docs/官方轉換程式.md](docs/官方轉換程式.md)。


### 真實程式裡有、手冊沒寫的寫法（已支援）

- `IF 條件 THEN 1110:ELSE 1300`：`ELSE` 前面可以有冒號（有一支樣本程式有 8 處）。
- `IF … THEN … ELSE YS$="" GOTO 96`：`THEN`／`ELSE` 裡的賦值後面可以直接接別的東西（沒有冒號），那一行剩下的部分（到 `ELSE` 或行尾）被丟掉、不報錯，所以這個 `GOTO` 其實不會執行，而是接著跑下一行。這是在 NC3000 真韌體上量到的（見 [docs/NC3000韌體.md](docs/NC3000韌體.md)）；同樣的寫法放在 `IF` 之外（`B$="" GOTO 30`、`A=1 PRINT "X"`）、或接在 `PRINT`／`FOR`／`LOCATE` 後面，真機都是 `SYNTAX ERROR`，我們也一樣。一支 MIDI 編輯程式（`MIDI EDITOR.BAS`）按任何音符鍵就會踩到這個寫法。
- `OPEN "名稱" FOR OUTPUTAS#1`、`FOR APPENDAS#1`：模式與 `AS` 之間可以不留空白（兩支樣本程式用到）。
- `CALL 57645`（`$E12D`）：程式把字元 `POKE` 進文字 RAM（`$02C0` 起）再呼叫它，推斷是「顯示文字 RAM」；本模擬器的文字 RAM 寫入即顯示，所以什麼都不用做（用到它的樣本程式因此能跑）。這是從用法推斷的，沒有文件。
- 還是編譯不過的幾行都是程式自己的錯字：一個程式的第 1320 行只有一個 `P`、第 1960 行 `RND(1)667` 少了運算子，另一個程式的第 5610 行把 `CIRCLE` 打成 `CLRCLE`。真機執行到那幾行同樣會報 SYNTAX ERROR。
