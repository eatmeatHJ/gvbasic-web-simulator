# 直接操作硬體的機器碼遊戲（未壓縮的原始分頁）

本文以一個 65,536 位元組（2003-04）的橫向捲軸動作遊戲 `.bin` 為例（某款 NES 遊戲的移植版，檔案必須自備，不在專案裡）：標題畫面、過場、第一關都在模擬器裡跑得起來。它**沒有壓縮**，是原始的 2 個 32 KB 分頁，和[大型機器碼映像](大型機器碼映像.md)同一類，但那一類是走 BIOS 常式，這個遊戲**直接操作硬體暫存器**，所以另做了一層硬體層（[web/wqxhw.js](../web/wqxhw.js)）。

## 檔案結構

- 用 PC1000／NC1020 傾印的區塊順序對映（`+0x4000→$4000`、`+0x6000→$6000`、`+0x0000→$8000`、`+0x2000→$A000`）：
  - 檔案 `0x4000`：檔頭 `40 00` 加遊戲名稱字串，`+0x18` 是 `JMP $402C`（**入口**），`+0x1B` 是簽章 `A5 AA 55`。
  - 檔案 `0x0000` 的第一條 `JMP $811A` 落在 `$8000` 區塊內，與對映互相印證。
  - 第 2 頁幾乎都是 `FF`，只有一小段程式（遊戲啟動時用分頁暫存器切過去，複製到 RAM `$2C00`，再切回來）。
- 偵測規則（`detectGame`）：大小是 32 KB 的整數倍，且 `+0x4018 = 4C`、`+0x401B..401D = A5 AA 55`。入口取自那條 `JMP`。

## 硬體（從遊戲自己的程式與行為讀出來的）

| 位址 | 用法 | 模型 |
|---|---|---|
| `$00` | 分頁暫存器：遊戲先讀、寫 1、再寫回原值 | 頁是相對的（和大型映像一樣，起始值任意） |
| `$01` | 計時器 0 旗標，讀後清除；遊戲每個畫面結束時 `LDA $01 / AND #1 / BEQ` 等它＝**影格同步** | 由模擬器依「幀率」設定旗標；等待時 CPU 休眠 |
| `$09` | 鍵盤：選線，依序寫 `04 08 40 80 20`（每次寫一個，之後歸零） | 記下選了哪些線 |
| `$08` | 鍵盤：讀回行，**1＝按下**；同時寫 `$15=$FC` | 回傳選中線上有按下的鍵的行位元 |
| `$10 $11 $14 $19 $01` | 開機時設一次計時器，之後沒再用 | 當 RAM |
| `$19C0`–`$1FFF` | LCD 位元圖，每列 20 位元組（遊戲在 `$0800`–`$0FFF` 組好再複製） | 沿用裝置本來的螢幕 |

**沒有用到中斷**（沒有 `CLI`），也沒有 BIOS 或 `INT` 呼叫，所以不需要 BIOS 那一層。

### 鍵盤矩陣

遊戲的掃描常式（`$413E`–`$4230`）把五條線的讀值組成按鍵位元 `$4C`。用在遊戲中逐一按住測試的結果：

| 功能 | 線／位元 | 把握 | 預設鍵 |
|---|---|---|---|
| 向左 | `04` bit0 | 確定 | ← |
| 向右 | `04` bit2 | 確定 | → |
| 跳躍 | `40` bit7 | 確定 | Z 或空白 |
| 加速／發射 | `40` bit3 | 確定（按住時捲動明顯變快） | X |
| 開始 | `80` bit5 | 確定（標題畫面按下才會開始） | Enter |
| 下 | `04` bit1 | 推測（依位元順序；開頭沒看到效果） | ↓ |
| 上 | `08` bit1 | 推測 | ↑ |
| 暫停？ | `80` bit3 | 不確定：常式對它做「翻轉 `$0907`」的處理 | P |
| — | `80` bit2、`20` bit0 | 不確定：特殊處理（跳到 `$4040`、設 `$0904`），沒有對應鍵 | 無 |

三個鍵同時按（跳躍＋加速＋開始＝`$4C=$D0`）會設 `$0905`，應是軟重置組合。真機上這些位元對應哪些實體鍵不明，上表是依遊戲的用法安排的。

## 幀率

遊戲在 CPU 上算一個畫面約 3.5 萬條指令，等 `$01` 的旗標才進下一畫面，所以速度＝旗標頻率。真機的計時器週期不明（也沒有任何文件），預設 30 幀/秒，側欄可改 15–60。依據：移植版的主角每幀走約 0.78 像素（NES 一幀約 1.5625 像素，縮成一半），30 幀/秒走起來接近原作的節奏；關卡時間倒數約每秒一格。

## 還沒做／不確定

- 沒有聲音：遊戲沒有碰蜂鳴器暫存器（`$18`），所以應該本來就是靜音的。
- 上、下鍵與 P 鍵的功能只是推測；需要遊戲進行到特定情況（例如拿到道具或進入管道）才看得出來。
- 幀率是估計。

## 工具

`node web/check_hwgame.js [檔案] [秒數] [-p 畫面.png] [-k "right:500-1500,z:800-900"] [-r "80.5:1000-1300"]`：不開瀏覽器，用硬體層跑一段時間，印出 LCD（可存成 PNG）。`-k` 按 UI 鍵、`-r` 直接按「線.位元」（十六進位線）。
