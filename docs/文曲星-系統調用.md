# 文曲星機器碼的系統調用（要做「CALL／BIN 沙盒」時的規格）

## 來源

《6502编程大奥秘》（徐宏海，2003-10-15；CHM，內部目錄 `文曲星编程/wqxpage/…`），作者開發過 CC800、PC1000、NC1020 的除錯工具，前言特別感謝 SUN。CSDN 頁面上「專為 NES 的 6502 開發者」的簡介是錯的，書本身是文曲星專用。

- 這是別人的著作，**只放在本機**，不放進專案；本文件只記規格事實。
- 書以 **NC1020** 為主要對象。PC1000／CC800 是否相同，只有部分得到印證（見最後一節）。
- 讀取方式：Windows 的 `hh -decompile` 只解得出目錄，改用 [tools/chm_extract.py](../tools/chm_extract.py)（純 Python、唯讀）。

## `INT` 指令就是 OS 呼叫（天然的攔截點）

機器碼 `00`（BRK）後面接兩個位元組：`INT $pppp` = `00 pp pp`。前一個位元組是**頁碼**，後一個是該頁表格裡的**項目編號**，系統去查表跳過去執行。`INT $C0xx` 比較特別，不是切到 C0 頁，而是在 `(0A)=00` 時用 `C000–DFFF` 的表。

模擬器的做法：攔下 BRK，依 `(頁碼, 項目)` 呼叫對應的 JS 函式，等同 DOSBox 攔截 `INT 21h`。

## 書裡有記載、第一批要做的呼叫

| 呼叫 | 功能 | 參數／備註 |
|---|---|---|
| `INT $8A2E` | 清除 LCD | |
| `INT $8A15` | 更新 LCD | 小字模式 `(0402)=01 (0403)=00`，大字模式 `(0402)=00 (0403)=01`，`(042D)=(042E)=FF`；寫完螢幕 RAM 後要呼叫它才會顯示 |
| `INT $C008` / `$C007` | 讀按鍵 | 掃描碼回在 A |
| `JSR $E02A` | 延時 | X 暫存器決定長短 |
| `JSR $E02D` | 延時 | Y 暫存器決定長短 |
| `JSR $E917` | 讀快閃資料 | `(05B4)`=頁碼，`(C8)(C9)`=位址，Y=偏移，結果在 A |
| `INT $021A` | 電量檢測 | 結果 0 = 電力足 |
| `INT $C30B` / `$C30C` | 畫線 / 畫方塊 | `(043F,0440)`=(X1,Y1)，`(0441,0442)`=(X2,Y2)，`(0445)`=01 畫 / 00 清 |
| `INT $C30E` / `$C30F` | 畫圓 / 畫橢圓 | 圓心 `(043F,0440)`，半徑 `(0452)`；橢圓寬 `(0457)` 高 `(0458)` |
| `INT $C30A` / `$C310` / `$C311` | 填滿方塊 / 圓 / 橢圓 | 參數同上 |
| `INT $C312` | 彈出訊息框 | A=0，X/Y=文字表位址（細節在書的「彈出式信息框」） |

螢幕文字 RAM 從 `$02C0` 起（與參考模擬器的 `textbuffer=704` 相符）。另外還有選單、輸入法、等級棒、鬧鐘、時間設定、內建遊戲等約 40 個 `INT`，用到再查。

## BIN 檔的格式（NC1020）

- **小於 8 KB**：系統把它整個載入 RAM `$2000` 開始執行。檔頭：`2000–2002: AA A5 5A`、`2003–2005` 實際長度、`2006: 20`、`2007: 4C`、`2008–2009` 入口位址、`200A–200F: 70 03 31 03 FF FF`，程式從 `$2010` 開始。
- **大於 8 KB**：第一次執行時（出現「裝入中…」進度條）系統找一個空閒的快閃頁，把它放到 `$4000` 開始。檔頭：`4000–4006: AE EE EA 00 20 00 20`、`4007: 4C`、`4008–4009` 入口位址、`400A–400F: 70 03 10 03 FF FF`，程式從 `$4010` 開始。
- 系統另外用「閃存分配表」記錄哪些快閃區塊已使用，用「BIN 文件表」記錄檔名、日期與大小；手工製作 BIN 時兩個表都要登記。

## 書裡沒有、仍然未知的

- `0xE135`、`0xE13B`（大型機器碼映像用到）、`0xE12D`＝57645（有的樣本程式用到；程式先把字元 `POKE` 進 `$02C0` 起的文字 RAM 再呼叫它，所以推斷是「顯示文字 RAM」，模擬器照這個推斷當成重繪）、`0x8B3D`＝35645（另一支樣本程式用到）：書裡查不到。
- `PEEK(1015)`：書裡沒有時鐘位址；NC3000 韌體確認它是小時，1016–1021 依序是分、秒、年、月、日、星期（見 [NC3000韌體.md](NC3000韌體.md)）。
- 大型機器碼映像（`GVbasic+.bin`）的檔頭不是上面兩種格式（它是 192 KB 的整包，開頭就是機器碼），所以它是怎麼被「安裝」（有些說明書稱「植入」）的，書裡的 BIN 格式不能直接套用。
- `0xE02A` 在大型映像（PC1000／CC800）和書（NC1020）裡的用法一致，顯示這個位址至少在這幾個機種之間相同；其他呼叫沒有這樣的印證。

## 目前的實作狀態（web/wqxos.js）

已實作：`INT $8A2E`、`$8A15`（不分大小字）、`$C008`／`$C007`（都是等按鍵）、`$021A`、`$C30A`–`$C311`（畫線、方塊、圓、橢圓與填滿）、`$C312`（訊息框，位置與大小為估計）、`JSR $E02A`／`$E02D`（延時，單位估計為 1 ms）、`JSR $E917`（沒有快閃資料時回傳 `$FF`）。

尚未實作：「小字」顯示模式（6 列 × 26 欄）、選單與輸入法等 `INT $C2xx`／`$C3xx` 其他項目、時間與內建程式類的 `INT`。遇到時會停下並指出是哪一個。
