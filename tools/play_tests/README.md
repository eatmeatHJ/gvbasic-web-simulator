# PLAY / BEEP / 迴圈速度的量測套件

> **2026-10 補充：這套測試在官方 NC3000 仿真器上不會有聲音。** 用自製的 NC3000 仿真跑同一份真韌體（見 [docs/NC3000韌體.md](../../docs/NC3000韌體.md)）發現，那份韌體的 GVBASIC 把 `PLAY` 當成 `REM`（整行跳過，連同後面用 `:` 接的語句），只有 `BEEP` 會響。所以在官方仿真器上錄不到 `PLAY` 的音；除非你有別的機型（NC1020／NC2000 等，或哈電族版本）的真機或仿真器，否則這套測試派不上用場。`BEEP` 與迴圈速度（第 9–11 項）仍然有意義。
>
> 以下是原本的說明。

目的：`PLAY` 的音長、八度、休止符怎麼算，`BEEP` 的音高與長度，以及 `FOR…NEXT` 迴圈的速度，目前模擬器裡都是估計值。這套東西讓你在**官方的文曲星仿真器**（`wqxsim.exe`）上執行幾支很短的測試程式，把聲音錄下來，再用一支分析程式把每個音的長度、音高量出來。

## 檔案

| 檔案 | 用途 |
|---|---|
| `PLAYT1.BAS`（原始碼 `PLAYT1.txt`） | 核心測試：一次跑完 15 項，每項之間按一個鍵。只用真機程式裡出現過的 `PLAY` 寫法，不會出錯 |
| `PLAYT2.BAS`（原始碼 `PLAYT2.txt`） | 可能在真機上出錯的寫法（`#`、`+`、`-`、`O0`、`O8`、`L0`、`T`、`V`、小寫、附點…），**一次只跑一個編號**，出錯就記下畫面上的訊息 |
| `analyze_play.py` | 讀取錄音檔（16 位元 PCM 的 WAV），印出每個音的起點、長度、音高、音名、音量和前面的靜音長度；純 Python，不需要安裝套件 |

重新產生 `.BAS`：在專案根目錄執行 `node tools/txt2bas.js tools/play_tests -o tools/play_tests`。

## 步驟

1. **把兩支程式放進仿真器。** 仿真器按右鍵，選「文件下載」，類型選 `.bas`（轉換成文曲星格式後的 Basic 程式），選 `PLAYT1.BAS` 和 `PLAYT2.BAS`。然後在仿真器裡進入 GVBASIC（官方說明：F7 鍵是「計算／換算」，GVBASIC 在那一組裡），選程式，按輸入鍵（Enter）執行。
2. **準備錄音。** 用 Audacity（免費）：音訊主機選 **Windows WASAPI**，錄音裝置選你喇叭的 **loopback**（有些電腦叫「立體聲混音」）。這樣錄到的是電腦播出來的聲音，不是麥克風，沒有雜音。電腦音量調到中等，別讓波形削頂。播放仿真器的聲音，確認 Audacity 的錄音表有跳動。
3. **開始錄音，再開始測試。** 先按 Audacity 的錄音鈕，再在仿真器按一個鍵開始。`PLAYT1` 每一項會在畫面印出編號並播放，接著寫「KEY」等你按下一個鍵。**請等聲音完全停了再按**，這樣每一項之間有一段靜音，分析時看得出來。
4. **存檔。** 跑完停止錄音，File > Export > Export as WAV，編碼選「Signed 16-bit PCM」。
5. **分析。**
   ```
   python tools/play_tests/analyze_play.py 你的錄音.wav --csv 結果.csv
   ```
   把畫面上印出的表貼給我（或把 `結果.csv` 給我）。另外請告訴我：測試過程中畫面上有沒有出現錯誤訊息、有沒有聽到按鍵的「嗶」聲（按鍵聲會被當成多出來的音，我認得出來）。
6. **`PLAYT2`**：每個編號各錄一段（或把幾個編號連續錄在同一個檔，中間留靜音）。執行時它會問編號。**沒有聲音或畫面出現錯誤訊息，也是有用的結果**，請把訊息抄給我。

## 每一項在量什麼，以及目前模擬器的假設

目前模擬器把「整音符」當成 1.6 秒，`L` 當成「1／n 音符」，`O4` 的 `C` 是中央 C（262 Hz），`BEEP` 是 4485 Hz、0.05 秒（在 NC3000 真韌體上量到的值）。下表是這些假設算出來的值，量到的如果不一樣，就是假設錯了。

| 項 | 內容 | 目前假設會得到 |
|---|---|---|
| 1 | `O4L8CDEFGAB` | 七個音，262 294 330 349 392 440 494 Hz，各 0.2 s |
| 2 | `O1…O4` 的 `C` | 33、65、131、262 Hz，各 0.2 s |
| 3 | `L5 20 30 32 33 40 64`，C 與 G 交替 | 0.32 0.08 0.053 0.05 0.048 0.04 0.025 s |
| 4 | `L1 2 3 4 6 8 10 12 16`，C 與 G 交替 | 1.6 0.8 0.533 0.4 0.267 0.2 0.16 0.133 0.1 s |
| 5 | 沒有 `O` 也沒有 `L`：`CGCGCG` | 預設八度 4、預設 `L4`：每個音 0.4 s |
| 6 | 音符後面接數字：`O4L8C4G4C16G16C1G` | 0.4 0.4 0.1 0.1 1.6 0.2 s（數字當作這個音自己的 `L`） |
| 7A–7E | 休止符：空白、兩個空白、`P`、`P4`、`P16` | 靜音 0.2、0.4、0.2、0.4、0.1 s |
| 8 | `PLAY` 之後立刻 `BEEP` | C 0.8 s，然後 BEEP 0.05 s，再 G 0.2 s，三個音接續（假設 `PLAY` 會等聲音播完） |
| 9 | `BEEP` 三次 | 三個 0.05 s、4485 Hz |
| 10 | `BEEP`，`FOR I=1 TO 500:NEXT I`，`BEEP`，1000 圈，`BEEP`，2000 圈，`BEEP` | 預設速度 3000 語句／秒：靠近的兩個嗶聲中間約 0.17、0.33、0.67 s（扣掉嗶聲本身 0.05 s） |
| 11 | `BEEP`，500 圈的 `A=A+1`，`BEEP` | 兩個嗶聲相隔約 0.33 s（一圈兩個語句） |

注意：第 10、11 項量到的是**官方仿真器**的速度，它可能快於或接近真機，不一定等於真機。

`PLAYT2` 的編號：1 `O5–O7`、2 `O0`、3 `O8`、4 `#` 升記號、5 `+` 升記號、6 `-` 降記號、7 `L0`、8 `L100`／`L128`／`L200`、9 `L255`／`L256`、10 `T` 速度、11 `V` 音量、12 小寫字母、13 附點、14 空字串與無意義的字元。

## 分析程式的限制

- 兩個**同音高**的音接在一起會被當成一個音（測試程式已經讓相鄰的音高不同）。
- 長度的誤差約半個週期（65 Hz 約 7 ms，500 Hz 約 1 ms）。
- 分析程式自己有測試：`python tools/play_tests/analyze_play.py --selftest`。
