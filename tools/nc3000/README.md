# NC3000 真韌體仿真（分析用）

用 6502 核心加上這台機器的硬體模型，讓 NC3000 的真韌體在 Node 裡跑起來。目的不是做另一個遊戲機仿真器，而是**把韌體當成可以問問題的標準答案**（`PLAY` 的音長與八度、BASIC 的速度、各種語意細節），結果寫進 `docs/NC3000韌體.md`。

**這個資料夾不含任何韌體或字型資料。** 韌體有版權，要自己從官方仿真器的安裝檔取出，放在本機的某個資料夾（預設 `tools/nc3000/fw/`，不要放進專案發佈）。取出用 `extract_fw.js`（只讀取安裝檔，不會執行它；可以直接給 `.zip`）：

```bash
node tools/nc3000/extract_fw.js 下載的\winsim_nc3000.zip
```

做法的細節見 `docs/NC3000韌體.md` 開頭。資料夾裡要有：

- `obj.bin`：1 MB 的 NOR（作業系統 ROM）
- `nd.bin`：NAND 傾印，每頁 528 位元組（512 資料 + 16 備用）

然後用環境變數指定位置（預設是這個資料夾下的 `fw/`）：

```bash
NC3000_FW=/path/to/folder node tools/nc3000/boot_demo.js out.png
```

## 檔案

| 檔案 | 內容 |
|---|---|
| `extract_fw.js`, `lh5.js` | 從官方仿真器的安裝檔（`.zip` 或裡面的 `.exe`）取出 `obj.bin`、`nd.bin` 等檔案；`lh5.js` 是 LHA `-lh5-` 解壓縮（照公開的演算法寫） |
| `cpu.js` | NMOS 6502，含週期數與十進位模式，未公開的操作碼當成同長度的 NOP；`test_cpu.js` 跑 Klaus Dormann 的功能測試（`ref/cputest/`），目前通過 |
| `machine.js` | 機器模型：RAM、NOR（含 AMD 寫入／清除指令）、NAND（含寫入／清除）、分頁暫存器、鍵盤矩陣、中斷與畫面節拍、待機與按鍵喚醒 |
| `keys.js` | 從韌體自己的碼表（ROM `$ED05`）取出「鍵碼 → 矩陣位置」 |
| `sim.js` | 好用的外殼：載入韌體、`run(n)` 跑 n 個畫面（1/64 秒）、`tap(鍵碼)`、`snap()`／`save()` 存 LCD 圖、`boot()` 開機到主選單 |
| `shot.js` | 把 LCD 畫面存成 PNG 拼圖 |
| `basic.js` | 在韌體自己的 BASIC 編輯器裡打字（沒有數字鍵：輸入模式、符號表的操作都包在 `typer(s).type(...)`）、`openEditor(s)` 從主選單走到編輯器 |
| `run_program.js` | 打一個程式（`PROG='行1\|行2'`）、存成 TB、執行，印最後的文字畫面和蜂鳴器的音（音高與長度，用 CPU 週期數） |
| `loop_speed.js` | 數解譯器每圈 `NEXT` 之間的 CPU 週期，量各種語句的速度 |
| `boot_demo.js` | 開機並存五張圖（啟動訊息、問題、Logo、主選單、辭典） |

## 用法範例

```js
const { make } = require('./sim.js');
const s = make();
s.boot();                 // 回答「保留」，等 Logo，按 Enter 進主選單
s.tap(0x06);              // 英漢辭典
s.run(400); s.snap();
s.save('shot.png', 2);
```

## 現況

開機、中文顯示、鍵盤、主選單、辭典、計算／換算選單、**BASIC 編輯器與執行**都能用。`boot()` 會在修復完成後把根目錄補到韌體要的區塊（細節見 `docs/NC3000韌體.md`），所以 `/sysdir/…` 的熱鍵程式都載得進來。已經量到：這份韌體的 `PLAY` 等同 `REM`（沒有聲音）、`BEEP` 約 4.5 kHz／50 毫秒、BASIC 每秒約 1,500–4,400 個簡單語句。時鐘（RTC）不會走，聲音沒有接到電腦的喇叭，只量蜂鳴器暫存器的變化。

## 注意

- 傾印的列號要加 64 才是韌體看到的列號（`machine.js` 的 `nandBase`），傾印缺前兩個區塊；少了這個修正，系統修復會失敗。
- 模型是「看韌體怎麼用、就怎麼回答」寫出來的，不是晶片的完整規格；暫存器不認得的位元回傳寫入的值。時序（計時基礎每畫面 4 次、第二來源每 32 畫面一次）是從韌體的計數方式推出來的，速度對不對還沒有獨立驗證。
